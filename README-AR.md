# 🏦 نظام إدارة البنك - المشروع المتكامل 🚀

تطبيق نظام بنكي احترافي تم تطويره بلغة **C++**، مصمم لإدارة العمليات المصرفية والوصول الإداري من خلال نهج تطويري منظم ومرحلي.

---

## 🏗️ رحلة المشروع ومحطاته الرئيسية

### 1️⃣ المرحلة الأولى: التأسيس (V1) 📊
**إدارة العملاء الأساسية**
* 👥 **الهدف:** بناء النظام الأساسي باستخدام عمليات CRUD (إنشاء، قراءة، تحديث، حذف).
* 🛠️ **المميزات:** التحكم الكامل في سجلات العملاء بكفاءة.
* 💾 **تقنياً:** تمت معالجة البيانات عبر `Vectors` وتخزينها بشكل دائم في ملف `Clients.txt`.

### 2️⃣ المرحلة الثانية: المحرك المالي (V2) 💸
**العمليات المصرفية والمنطق البرمجي**
* 💳 **الهدف:** تحويل النظام إلى تطبيق مالي متكامل.
* 🛠️ **المميزات:** إضافة نظام معاملات قوي يشمل الإيداع، السحب، وتقارير الأرصدة.
* 💾 **تقنياً:** تطبيق تحققات صارمة لمنع السحب الزائد وضمان دقة البيانات.

### 3️⃣ المرحلة الثالثة: طبقة الأمان (V3) 🔐
**الوصول الإداري والصلاحيات**
* 🔑 **الهدف:** تنفيذ نظام إداري احترافي.
* 🛠️ **المميزات:** إضافة شاشة دخول آمنة ونظام صلاحيات دقيق لجميع مميزات النظام.
* 💾 **تقنياً:** استخدام `Bitwise Operators` لإدارة الصلاحيات بكفاءة عالية، وتتبع حالة المستخدم الحالي (`CurrentUser`).

---

## 💻 هيكلية الكود والرؤية المستقبلية 🧬

### الهيكلية الحالية: البرمجة الإجرائية (Procedural / Functional Programming)
بُني المشروع بالكامل باستخدام **البرمجة الإجرائية**، مع التركيز على الدوال المنظمة، وهياكل البيانات، وتدفق التحكم النظيف. كان هذا النهج ضرورياً لإتقان المنطق وتدفق البيانات في النظام البنكي.

### التطور المستقبلي: الانتقال إلى البرمجة الكائنية (OOP)
يعد هذا المشروع حجر الأساس لمرحلتي التطويرية القادمة. أخطط لإعادة هيكلة النظام بالكامل باستخدام **البرمجة الكائنية (OOP)**، مع توظيف الكلاسات (Classes)، الوراثة (Inheritance)، وتعدد الأشكال (Polymorphism). سيؤدي هذا التحول إلى تحسين قابلية التوسع، إعادة استخدام الكود، وسهولة الصيانة للميزات البنكية المستقبلية.
